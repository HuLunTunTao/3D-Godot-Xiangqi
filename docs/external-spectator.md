# 本机外部对局观战

游戏可作为只读可视化端连接到本机 TCP 数据源。Godot 是 TCP **客户端**，因此外部进程或独立 relay 应监听端口并向已连接的客户端推送数据。外部进程仍是对局的唯一权威；游戏不回传走子、不等待确认，也不会启动 AI 搜索。

## 使用

在开始面板选择“外部对局观战（本机 TCP）”，填写主机、端口、红黑方名称、显示延迟和附加信息，然后开始。默认地址是 `127.0.0.1:19190`。

数据源以 UTF-8 NDJSON 发送，每行一个 JSON 快照：

```json
{"version":1,"session":"demo-1","seq":1,"type":"snapshot","fen":"rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1","red_name":"小红","black_name":"小黑","latency_ms":18,"info":"第 3 台引擎"}
```

必填字段是 `fen`；`type` 缺省时等同 `snapshot`。`session` 和单调递增的 `seq` 强烈建议提供：新会话会重置序号，同一会话的重复或旧序号会被丢弃。可选字段 `last_move`（如 `h2e2`）只用于棋谱展示。

## 性能和可靠性约定

- 发送方必须把观战端当成可慢、可断开的消费者，不能等待它的确认。
- 游戏每帧最多读取 32 行，且只应用其中最新的有效快照；中间局面可被合并丢弃。
- 若消息断序、重连或棋盘落后，下一条完整 FEN 会直接重建棋盘，而不是补跑所有动画。
- 单行超过 64 KiB 会被丢弃，连接会自动重试；最后一个有效局面会保留在屏幕上。

因此，高频外部计算不会因渲染、动画或 UI 而被反压。生产端应独立维护有界发送队列，并在队满时以最新完整快照替换旧增量。
